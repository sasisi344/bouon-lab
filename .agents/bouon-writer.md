# BouonLab ライティング／シンキングルール：本音と建前分析

`/bouon-lab` コマンド実行時に `CLAUDE.md` と併せて読み込む、防音Lab記事制作の思考フレームワーク。
検索キーワードの「建前（公言する理由）」と「本音（実際の心理）」を分離して把握し、本音に触れる記事にすることで刺さる確率を上げる。

## 目的

表面的な検索意図（建前）の裏には、コンプレックス・不安・見栄・焦りからくる本音が隠れているケースが多い。
記事でその本音に触れられるかどうかが、読者に「わかってくれている」と思わせられるかの分かれ目になる。

`.agents/persona/00_Persona-Omega.md` の検閲フィルター（誇大広告排除／二次リスク提示／ROI／QOL帰結）は執筆後の**品質チェック**、本ルールは執筆前の**読者心理の掘り下げ**を担当する。両者はセットで使う。

## シンキングルール：KWごとの本音・建前分析手順

1. 対象KW（および関連KW・サジェスト）を洗い出す
2. KWごとに「建前（公言する理由）」と「本音（実際の心理）」をペアで書き出す。3〜8ペア程度、表形式推奨:

   | # | 建前（公言する理由） | 本音（実際の心理） |
   | --- | --- | --- |
   | 1 | ... | ... |

3. 本音の中でも特に強いもの（諦め、後悔への恐怖、見栄、焦り、粗大ゴミ化への恐怖など）を1〜2個選び、「裏読み」として1段深掘りする（なぜその本音を隠すのか／何を恐れているのか）
4. 深掘りした本音に対する具体的な解決策・妥協案を洗い出す（価格を下げる方法、代替案、正直な限界表明など）

## ライティングルール：記事構成への落とし込み

- **導入**：建前（表面の検索意図）に共感して入る
- **中盤**：本音（不安・コンプレックス）を先回りして言語化する → 「わかってくれている」信頼を作る
- **後半**：本音に対する具体的な解決策を提示する（低価格帯モデル、代替案、正直な限界表明＋誠実な情報源としての信頼獲得）
- 仕上げ段階で `00_Persona-Omega.md` の4フィルター（誇大広告排除／二次リスク／ROI／QOL帰結）を通し、整合性を確認する

## プロンプト例

```
以下のキーワードについて、防音Labの「本音と建前」シンキングルールに従って分析し、
記事の構成案を作ってください。

対象KW: {キーワード}

手順:
1. 想定される検索者ごとに「建前（公言する理由）」と「本音（実際の心理）」を
   表形式で3〜8ペア洗い出す
2. 本音の中で特に強いもの1〜2個を選び、その裏にある心理
   （諦め・見栄・焦り・恐怖など）を1段深掘りする
3. 深掘りした本音に対する具体的な解決策・妥協案を挙げる
4. 導入（建前に共感）→中盤（本音の言語化）→後半（解決策提示）の
   記事構成案を見出し案付きで作る
5. .agents/persona/00_Persona-Omega.md のフィルター
   （誇大広告排除／二次リスク提示／ROI／QOL帰結）を通して整合性を確認する

出力形式: 本音・建前ペア表 → 裏読み → 記事構成案（見出し案付き）
```

## 元分析（防音室KW サンプル）

| # | 建前（公言する理由） | 本音（実際の心理） |
| --- | --- | --- |
| 1 | 騒音問題を解決したい | 高価すぎて手が出ない／設置スペースがない |
| 2 | 近隣に迷惑をかけたくない | 実はもうクレームが来ていて後がない、焦っている |
| 3 | 本格的に趣味・楽器に取り組みたい | 見栄を張りたい／SNSや配信で「ちゃんとした環境」に見せたい |
| 4 | 性能・スペックを比較して選びたい | 選択肢が多すぎて決められない、失敗して後悔したくない |
| 5 | 長く使える製品を選びたい | 引っ越し・賃貸解約時に処分できるか不安（粗大ゴミ化への恐怖） |
| 6 | 家族に配慮している | 配偶者・親から「うるさい」と言われて揉めたくないだけ |
| 7 | 防音室で完全に解決すると思っている | 内心「本当に効果あるのか」半信半疑（簡易防音への不信） |
| 8 | 自宅で楽器練習・配信環境を整えたい | 賃貸で工事できない、原状回復義務がネック |

**裏読み例**:「高価・設置場所がない」は予算・物理制約の話ではなく「欲しいけど諦めている自分」への言い訳になっているケースが多い。「組み立て式」「レンタル」「簡易防音＋吸音材の合わせ技」のような妥協案の提示が刺さる。
