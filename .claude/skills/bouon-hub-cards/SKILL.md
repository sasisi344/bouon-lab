# BouonLab 入口カード（hub）運用

トップの「課題別ハブから読み進める」の6枚のカードに、どの記事を出すかを管理するルール。経緯と要件の全文は `.workspace/.task/top-category-chenge-task.md`（T-21）。

## 仕組み（2026-10-08 確定）

- 記事のfrontmatterに任意項目 `hub` を付けた記事だけが、カードの候補になる。**付けていない記事は、どのカードにも出ない**
- 各カードは、`hub` にそのkeyを持つ**全記事を母集団**とし、**アクセスごとにランダムで3本**を表示する（ブラウザ側で抽選。特定の3本にクリックが集中するのを避けるため）
- 表示順の数字は抽選には使わない。**JS無効時と検索エンジンに見える初期表示（1〜3）**を決めるだけ
- カードは `src/data/hubClusters.ts` の配列順に表示（2列グリッド、スマホは1列）。「N件」はボタンのリンク先カテゴリの記事数
- 記事ページの「次のステップ」は、`nextSteps` の手動指定がなければ、その記事の `hub` のうち**表示順が最小のクラスター**を使う。`hub` のない記事はカテゴリへのリンクになる

## 書き方

```yaml
hub:
  sound-basics: 1    # クラスターのkey: 表示順（1が最上位）
  sound-leak: 2      # 複数のクラスターに入れてもよい
```

- 表示順は**同じクラスター内で重複させない**（1の次は2、3…と続ける）。新しく足す記事は、そのクラスターの最大値+1
- 記事の本文は触らない。**`lastmod` は更新しない**（掲載管理だけの変更のため）
- keyを間違えるとビルドが失敗する（スキーマが `hubClusters.ts` の `HUB_CLUSTER_KEYS` と同期している）

## 6枚のカード（表示順・key）

| key | 見出し | リンク先 | 入れる記事の目安 |
|---|---|---|---|
| `soundproof-room` | 防音室を選ぶ | `/ja/soundproof-room/` | 防音室の比較・サイズ・種類・設置条件 |
| `soundproof-rental` | 防音賃貸・住まい探し | `/ja/soundproof-rental/` | 防音賃貸の探し方・相場・エリア別ガイド |
| `sound-leak` | 配信・楽器・在宅の音漏れ | `/ja/creator/` | 配信・楽器練習・在宅ワークの音漏れ対策 |
| `diy` | 自分で試す（DIY） | `/ja/diy/` | 費用を抑えた自作・賃貸でできる対策 |
| `sound-basics` | 音の仕組み・原因から調べる | `/ja/knowledge/` | 数値・規格・原因の解説（D値、TL値、ノイズ） |
| `money-market` | 費用・相場・補助金・市場データ | `/ja/money/` | 価格相場・ローン・補助金・市場規模 |

- 「ビジネス」のカードは作らない（流入が0.3%）。睡眠・騒音トラブル・在宅の記事は、独立カードにせず `sound-basics` か `sound-leak` に入れる
- 見出し・文言・カード数の変更は `hubClusters.ts` を直し、**ユーザーの確認を取る**。新しいkeyを足すときは `HUB_CLUSTER_KEYS` に追記する

## 運用方針（ユーザー決定、2026-10-08）

**一括で全記事に付けない。次の2つのタイミングでだけ、リストに入れる（テコ入れの手段として使う）。**

1. **記事が増えたとき**: 新記事の公開後、中核になる記事（そのテーマの入口になる・流入の見込みがある）だけを候補にする。**公開のたびに自動で付けない**
2. **アクセス解析で、伸ばしたい記事が出たとき**: 週報（`bouon-weekly-report`）やGSCで、順位は取れているがクリックが少ない、表示は多いが回遊が弱い、といった記事をカードに入れて流入を後押しする

### 掲載の判断基準

- そのカードの読者の用事（上の表）に合う記事か。**関連性の薄い記事を、母集団の数合わせで入れない**（元のキーワード部分一致で関連の薄い記事が出ていたのが、この仕組みを作った理由）
- 下書き（`draft: true`）でない
- 統合・削除済みの記事は付けない。統合した記事は `hub` も一緒に消えるので、統合先の記事に必要なら付ける

### 母集団の数

- 各カード**6本以上**を推奨（現状は4〜5本）。4本のカードは「4本から3本」を選ぶだけで、ランダムの効果が小さい
- 3本未満のカードは、あるものだけ出る。0本のカードは出ない

### 評価の読み方

- 抽選のため、**記事ごとの表示回数は揃わない**。記事別のクリック率は比較できない
- 評価はカード単位（GA4の `hub_click` のうち、`hub_cta` と `hub_entry` の合計）で見る
- 直接流入（トップ）はbot疑い（T-04）が未了のうちは、割り引いて見る

## 作業手順（掲載を変えるとき）

1. 対象記事のfrontmatterに `hub` を足す・消す・直す（上の「書き方」）
2. 一覧を再生成し、警告を確認する

   ```bash
   node .workspace/scripts/build-hub-list.mjs
   ```

   出力は `.workspace/.data-set/hub-cluster-list.md`（手編集しない）。警告は「draft記事に `hub` が付いている」「所属が3本未満」「所属が5本未満」「表示順の重複」「未知のkey」
3. `pnpm build` が通ることを確認する。トップのカードは、リロードで3本が入れ替わることを `pnpm preview` で見る
4. タスクの記録: 掲載を変えた日と理由を、効果を見るW-NNに書く（`bouon-task-ops`）。トップは重要な内部リンク元なので、変更後のGSC・GA4を週次確認で見る
