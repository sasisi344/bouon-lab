# BouonLab Threads運用ルール

作業フォルダは `.agents/threads-ops/` を使用する（`README.md`・`postlist.md`・`used-sources.md`・`drafts/snippet/`・`drafts/query-hook/`）。
運用の基本方針（収益導線・ビジュアル設計）は `bouon-growth-ops` skillを参照。本ファイルは投稿の**中身の作り方**を定義する。

投稿は目的の異なる2種類に大別し、混同しない。

## 投稿タイプ①: 小ネタ型（定期投稿・低コスト）

- **目的**: 更新頻度の確保・フォロワーの離脱防止。エンゲージメント最大化は狙わない
- **ソース**: 既存の公開記事（`src/content/ja/**/index.mdx`）から「へえ、と思わせる事実・数値・比較」を**1つだけ**抜き出す。記事の要約ではなく、1トピックに絞る
- **選定基準**（数値・比較・意外性を優先）:
  - dB換算の身近な例（洗濯機・電車・クラクション等）
  - 価格帯・補助額の対比（例: 100万円クラスと簡易ブースの差）
  - 制度・規約の意外な条件（例: 使用細則の実際の文言）
- **文字数**: 100〜200字程度。単体で完結させる（続きを読ませる前提にしない）
- **頻度**: 週2〜3本を目安（ユーザーの運用負荷に応じて調整）
- **リンク**: 元記事へのリンクは任意。なくても内容として成立させる
- 直近で使用した記事・トピックは`used-sources.md`で重複を避ける

## 投稿タイプ②: クエリ疑問オープナー型（長文・エンゲージメント重視）

- **目的**: リプライ・いいね・リポストなどのリアクション最大化。Threadsの長文投稿枠（最大500字）を活かし、他プラットフォームより深く書く
- **開始のフック**: 防音室・防音賃貸に関わる**実際の検索クエリ**（`effect-monitoring.md`・`weekly-task.md`の実データ、GSCエクスポート、`bouon-persona-thinking` skillの本音と建前分析）に基づいた疑問形で書き出す。検索者の言葉をそのまま、または近い表現で再現し、「これは自分のことだ」と数秒で認識させる（`bouon-persona-thinking` skillの「指名検索・個別クエリ記事における導入フックの厳格化」と同じ考え方をThreadsにも適用する）
- **架空のクエリを作らない**。必ず実データに基づくクエリ・悩みを起点にする
- **本文構成**:
  1. 疑問形の導入（検索者の言葉に近い表現）
  2. 本音の言語化（なぜその疑問を持つのか、不安の中身）
  3. 結論・具体的な答え（記事を読まなくても一定の価値が完結するボリュームで書く。要約ではなく実質的な回答にする）
  4. リアクションを誘発する一文で締める（例:「あなたの物件はどうでしたか？」といった問いかけ、または軽い意見表明で賛否を引き出す）
- **リンク**: 本文には入れず、1件目のリプライで元記事へ誘導する（本文内リンクはリーチが抑制される傾向があるため）
- **頻度**: 週1本を目安。量産せず、クオリティを優先する

## 共通ルール

- テンプレ化を避ける（フック・語順は投稿ごとに変える）
- 誇大表現・断定しすぎない書き方を守る（`.agents/persona/00_Persona-Omega.md`の検閲フィルターに準拠）
- 投稿後は必ず`.agents/threads-ops/postlist.md`に記録する（投稿タイプ・ソース記事またはクエリ・投稿日・投稿URL）
- 使用済みの記事・クエリは`.agents/threads-ops/used-sources.md`で管理し、次回選定時に重複チェックする
