# 検索意図マッチング（クエリ導出 → クエリ契約 → タイトル → description → 導入 → H2）

新規執筆・リライト・`/draft-plan` の全工程で使う。目的は「検索者が打った言葉」と「タイトル・本文が答えている質問」を一致させ、検索結果でクリックされ、着地後に離脱されない記事にすること。

**タイトルとH2はアウトライン（ドラフト）の段階で決める。** 本文を書き終えてからタイトルを付けると、本文の言いたいことに引っ張られてクエリから離れる。順番は「クエリを導く → タイトルとH2を決める → 本文を書く」で固定する。

本音と建前（`bouon-persona-thinking`）は**クエリ契約が決まった後**に使う。クエリに答えていない記事に本音フックを足しても読まれない。

## 背景（2026-10-15 GSC分析）

- 5〜10位のCTRが1.88%（3か月）。1ページ目に出ているのにクリックされていない
- CTRが高い記事（ベーストラップ8〜21%、ワンタッチ防音壁「評判」10.5%、ニトリ5.5%、ハウスメーカー7.7%）は、**検索語がそのままの語順でタイトル先頭にあり**、疑問形か結論の半分を見せ、検索結果では分からない判断材料（限界・買う前に）を約束していた
- 低CTRの主因は文章の巧拙ではなく**意図のずれ**だった（下記「失敗例」）

## Step 0. アウトライン段階でクエリを導く

`_inbox/` のアウトライン作成時、または `/draft-plan` の最初に行う。リライトでは、GSC画面でページを絞り込んだ実際の流入クエリを素材にする。

### 0-1. 素材を集める

| 素材 | 見るもの | 注意 |
|---|---|---|
| ラッコキーワードのサジェスト（`_inbox/`・`.task/query-check/`） | テーマの語を含むサジェストの全バリエーション | 無料枠は検索数が null。「サジェストに出る＝需要がある」までしか言えない |
| GSCのクエリ（`access-data/`、GSC画面の部分一致） | 既に表示されている語・順位 | 表示実績のある語は需要の裏付けとして最優先 |
| 検索結果（WebSearch、`standard`） | メインKW候補の上位5件のタイトルと、記事の種類 | 0-4で使う |

### 0-2. 同じ答えで満たせる語ごとにまとめる

サジェストの語を「検索者が欲しい答え」でグループに分ける。**1グループ＝1記事**。

- 同じ答えで満たせる語（「防音室 インターホン」「防音室 インターホン 聞こえない」）は同じ記事
- 答えが別の語（「防音室 インターホン」と「防音室 酸欠」）は、同じテーマでも別の記事か、別のH2
- 迷ったら2つの語で検索し、上位10件の重なりを見る。半分以上同じURLなら同じ記事、ほとんど重ならなければ別の記事にする（Googleが同じ意図と見なしているかの確認）

### 0-3. メインKWを1つ決める

グループの中から、タイトルに入れるメインKWを**1つだけ**選ぶ。残りはサブKW（2〜5個）にする。

選ぶ基準（上ほど優先）:

1. GSCで既に表示実績がある語
2. サジェストで派生語が多い語（「防音室 インターホン ○○」が多数ある＝需要の幹）
3. 検索者が欲しい答えが1つに定まる語
4. 自然な日本語のタイトルに入れられる語（助詞を足して読める）

### 0-4. 検索結果を確認する

メインKW候補で検索し、上位5件のタイトルと記事の種類をアウトラインに書き残す。

- **上位の種類**: 解説記事／比較・ランキング／商品・EC／公式サイト／地図・店舗／Q&Aサイト。解説記事がほとんど無い場合（ECや公式サイトばかり）は、情報記事で上位に入るのは難しい。メインKWを変えるか、サブKWに下げる
- **上位タイトルが共通して約束していること**: 自記事のタイトルには、上位にない判断材料を1つ入れる（差別化）
- **上位タイトルの語**: 上位が共通して使う語は、検索者とGoogleが期待している語。タイトルかH2に入れる

### 0-5. 既存記事とのカニバリを確認する

`.workspace/.data-set/interlink-postlist.md` とGSCで、同じメインKWを狙う既存記事がないか確認する。

- 既存記事が同じメインKWを狙っている → 新規記事にせず、既存記事への加筆（H2追加）に切り替える
- 既存記事が近いサブKWで表示されている → 役割を分け、相互に内部リンクする

### 0-6. アウトラインに書く項目

アウトライン（`_inbox/` のメモ、`_draft/` の下書き、`[!forAI]` ブロック）には以下を必ず書く。この内容が `/draft-plan` と本文執筆の前提になる。

```markdown
## クエリ設計
- メインKW: {1つ}（根拠: GSC表示 / サジェスト派生数 など）
- サブKW: {2〜5個}
- クエリ型: {6型のどれか}
- 欲しい答え: {1文}
- 検索結果で完結しない理由: {1文}
- 外してはいけない解釈: {意図が割れる場合のみ}
- 検索結果の上位5件: {記事の種類と、共通して約束していること}
- カニバリ確認: {なし / 既存slugと役割分担の内容}

## タイトル（確定案と予備案）
1. {確定案}（{字数}字・メインKWの位置）
2. {予備案}

## 見出し構成
- H2: {見出し}（対応KW: {メインKW or サブKW}）
- H2: ...
```

## Step 1. クエリ契約を書く（執筆前・必須）

Step 0で導いた内容を、構成・本文に入る前の約束として確定する。`/draft-plan` の提案カード、`[!forAI]` ブロック、リライトの診断メモに必ず残す。アウトラインに「クエリ設計」がある場合は、それをそのまま使う。

| 項目 | 書き方 | 取得元 |
|---|---|---|
| **メインクエリ（メインKW）** | 実際に検索される語をそのまま（語順・表記ゆれも実物どおり）。1記事に1つ | Step 0-3。自作の言い回しは不可 |
| **サブクエリ（サブKW）** | メインと同じ答えで満たせる関連語 2〜5個 | Step 0-2 |
| **クエリ型** | 下表の6型から1つ | — |
| **欲しい答え（1文）** | 検索者が記事を開いて最初に知りたいこと | 検索者の立場で書く。記事側の言いたいことではない |
| **検索結果で完結しない理由** | クリックしないと得られないもの（確かめ方・例外・比較表・自分の場合の判定） | これが書けない場合、CTRは上がらない前提で扱う |
| **外してはいけない解釈** | クエリを文字どおり読んだときの質問 | 記事の主題と違っても、冒頭で必ず答える |

### クエリ型

| 型 | クエリ例 | 検索者が欲しいもの |
|---|---|---|
| **直接回答型** | マンション 楽器 何時まで／防音室 何dB | 数値・時刻・可否の1語回答＋自分の場合の当てはめ方 |
| **効果確認型** | ワンタッチ防音壁 効果／ニトリ 防音 評判 | 効く・効かないの判定と、その境界線 |
| **費用型** | 防音 坪単価／防音室 費用 相場 | 金額の幅と、幅が出る条件 |
| **比較・選択型** | 防音室 ハウスメーカー おすすめ／防音工事 種類 | 候補の一覧と選ぶ基準 |
| **手順型** | ベーストラップ 自作／防音室 Wi-Fi 繋がらない | 原因と手順、必要な材料・時間 |
| **探索型** | シェアハウス 東京 音大生／楽器可 物件 探し方 | 具体的な探し先・候補の見つけ方（地名・対象者がそのまま入る） |

指名検索（製品名・施設名が主語）は上のいずれかの型に重ねて扱い、`bouon-persona-thinking` の「指名検索の導入フック厳格化」も適用する。

### 意図が割れるクエリの扱い

1つのクエリに解釈が2つ以上ある場合（例: 「ピアノ 住宅ローン」＝ピアノ本体をローンに入れたい／ピアノ室を建築費に入れたい）は、

1. 文字どおりの解釈（外してはいけない解釈）に**冒頭で短く答える**
2. そのうえで記事の主題へ橋渡しする
3. 主題と違う解釈を「本記事では扱いません」と切り捨てない

## Step 2. タイトルを作る

### 基本式

```
［メインクエリの語をそのままの語順で先頭に］＋［疑問、または結論の半分］＋［検索結果では得られない判断材料］
```

- メインクエリの語は**先頭15字以内**に置く。助詞を足して自然な文にしてよい（「ワンタッチ防音壁 効果」→「ワンタッチ防音壁は効果ある？」）
- 長さは本文タイトル28〜38字を目安にする（実際の`<title>`には「 | 防音Lab」が付く）
- 区切りは「｜」か「？」。1タイトルに区切りは1つまで

### 型別のタイトル

| 型 | 型の組み立て | 例 |
|---|---|---|
| 直接回答型 | クエリ？＋答えの形（幅・条件）＋確かめ方/例外 | マンションで楽器は何時まで？自分の物件の上限を3つの物差しで確かめる |
| 効果確認型 | 対象は効果ある？＋効く所と効かない所＋買う前の判断材料 | ニトリ防音は壁に効果ある？反響は減るが音漏れは止まらない |
| 費用型 | クエリの相場＋裏取り済みの数値幅＋差が出る条件 | ※数値は `bouon-research` で裏取りしたものだけ入れる |
| 比較・選択型 | クエリ＋対象数・比較軸＋選び方 | 防音室が作れるハウスメーカーおすすめ4社｜公式防音仕様を比較 |
| 手順型 | クエリ＋解決する症状＋手順の範囲 | ベーストラップ自作・設置ガイド｜低音こもりを解消する配置・測定 |
| 探索型 | 対象者＋場所・条件＋探し方 | 音大生のシェアハウス探し｜東京・関西で楽器OKの物件を見つける方法 |

### 数字をタイトルに入れるか

- **数字だけで答えが終わる場合**（何時まで・何dB）は、数字を出すなら「例外」「確かめ方」「自分の場合」を必ず添える。数字単体で言い切ると検索結果だけで用が済む
- **数字が判断材料になる場合**（費用の幅・比較の対象数）は、裏取り済みならタイトルに出す。数字が無いと探索型・費用型ではクリックされにくい
- タイトル・description・導入文の数字は**完全に一致させる**

### 禁止

- スペース区切りのキーワード並べ（「防音 注文住宅の坪単価」）
- 検索語を別の言葉に言い換えただけのタイトル（検索は「シェアハウス」なのにタイトルは「物件探し」）
- 「徹底解説」「完全ガイド」「網羅」だけで価値を示すこと（判断材料の代わりにならない）
- 誇大表現（Persona Ωフィルター）

## Step 3. description を作る（80〜120字）

```
前半（〜60字）: メインクエリの語＋結論（または結論の方向）
後半: 記事に何があるか（表・チェックリスト・試算・手順）＋誰向けか
```

- 1文目は検索者の疑問の形で始めてよい（「〇〇は本当に効くのか。」）
- 「〇〇ではなく」で始めて、検索者の質問を外す書き方は禁止（失敗例1）
- サブクエリの語を1〜2個、自然に含める

---

## Step 4. 導入（ファーストビュー）

`<RegionBanner />` の直後、スクロールせずに見える範囲で以下を満たす。

1. **1文目**: メインクエリを読者の言葉で言い直す（指名検索なら具体名から入る）
2. **2〜3文目**: 欲しい答えを返す。条件付きの答えなら条件も言う
3. **その次**: 検索結果で完結しない理由（この記事で分かる判定方法・例外）を1文で予告
4. 意図が割れるクエリでは、外してはいけない解釈への答えをここに入れる

本音への共感（`bouon-persona-thinking`）は答えの後に置く。答えより先に長い共感を置かない。

---

## Step 5. H2 にサブクエリを割り当てる

- サブクエリごとに、その語を含むH2（またはFAQのH3）を1つ対応させる
- H2見出しは検索語に近い言い回しにする（社内用語・造語だけの見出しにしない）
- どのH2にも割り当てられないサブクエリは、記事の対象外として契約から外す。他記事で拾うなら内部リンク先を決める

## KWの配置ルール（タイトル・見出し・本文）

GoogleはタイトルとH2を、ページが何についての記事かを判断する強い手がかりにする。検索者も検索結果と目次で「自分の語があるか」を見てクリックや読み進めを決める。以下を基本とし、日本語として不自然になる場合は自然さを優先する。

| 場所 | ルール |
|---|---|
| **title** | メインKWを必ず1つ入れる。構成語をすべて含め、なるべく検索された語順のまま先頭寄りに置く。サブKWは自然に入る場合のみ1つまで追加。同じ語を2回入れない |
| **description** | メインKWを1回入れる（検索語と一致した部分は検索結果で太字になる）。サブKWは1〜2個 |
| **導入（最初の100字）** | メインKWを1回入れる。言い換えではなく検索語そのままの形で |
| **H2** | メインKWに直接答えるH2（通常は最初か2番目）にメインKWを入れる。サブKWは対応するH2に入れる。目安として、まとめ・次のステップを除くH2の半数程度にメインKWかサブKWの語が入っている状態にする |
| **H2（上限）** | すべてのH2に同じKWを入れない。KWを入れる余地がない見出しに無理に押し込まない（過剰最適化と読みにくさの両方で逆効果） |
| **H3** | KWの言い換え・関連語（上位記事が共通して使う語、具体的な製品名・数値・場面）を使う。FAQのH3はサジェストの疑問形（「〜は何時まで？」）をそのまま使う |
| **slug** | 新規記事はメインKWを英語にしたもの（例: 防音室 インターホン → `soundproof-booth-intercom`）。既存記事のslugは変えない |
| **画像のalt** | 画像の内容を説明する。メインKWは内容に合う場合のみ入れる |
| **内部リンクの文言** | リンク先記事のメインKWを含む文言にする（「こちら」で済ませない） |

### やってはいけない配置

- KWを読点やスペースで並べる（「防音室｜インターホン｜聞こえない｜対策」）
- 意味の違う複数のメインKWを1タイトルに詰める（1記事1メインKW）
- 本文で同じKWを不自然に繰り返す（文の主語・目的語として自然に出る分で足りる）

## Step 6. 公開前のセルフチェック

すべて「はい」になるまで公開しない。

- [ ] メインKWが1つに決まっていて、既存記事とカニバリしていない
- [ ] メインクエリの語が、タイトル先頭15字以内にそのままの語順である
- [ ] メインKWがdescriptionと導入の最初の100字に、そのままの形で1回ずつある
- [ ] メインKWに直接答えるH2にメインKWがあり、サブKWが対応するH2/FAQにある（全H2への詰め込みはしていない）
- [ ] タイトルを読むだけで「この記事が何に答えるか」が分かる
- [ ] タイトルだけで答えが完結していない（クリックする理由がある）
- [ ] descriptionの前半にクエリ語と結論がある
- [ ] 導入3文以内で、欲しい答えを返している
- [ ] 外してはいけない解釈を切り捨てていない
- [ ] タイトル・description・導入・本文の数値が一致している
- [ ] 各サブクエリに対応するH2/FAQがある

## Step 7. 公開後の検証とリライトのきっかけ

GSCのエクスポートはページとクエリが別表のため、ページ単位のクエリはGSC画面で「ページ」を絞り込んでクエリタブを見る。

| 状態 | 判定 | 対応 |
|---|---|---|
| 10位以内でCTR 3%未満 | タイトル・descriptionの問題 | Step 2〜3の型に照らしてタイトルを直す（最優先） |
| 表示30回以上（3か月）のクエリの語が、タイトルにもH2にもない | 意図のずれ | そのクエリに答えるH2を足す。主要な流入クエリならタイトルも合わせる |
| 11〜20位 | 内容の不足 | H2追加・一次情報の追加で10位以内を狙う。タイトルだけ直しても効果は小さい |
| 21位以下で表示が多い | 記事とクエリの不一致 | タイトルを直すより、統合・作り直しを検討する（`bouon-rewrite-strategy`） |

**CTRの目標は「10位以内のページのCTR 5%以上」で測る。** サイト全体の平均CTR・平均順位は、20位以下の表示（例: ground-loop-noise-basics の60〜70位で885表示）に引きずられるため、タイトル改善の効果測定には使わない。

## 失敗例（2026-10-15 GSC直近3か月）

| # | クエリ（表示・順位・クリック） | 記事 | 何がずれていたか |
|---|---|---|---|
| 1 | ピアノ 住宅ローン（121・11位・0） | money/piano-soundproof-mortgage-tax-guide | 文字どおりの解釈（ピアノ本体をローンに入れたい）を、description・導入で「ピアノ本体のローンではなく」と外していた |
| 2 | 防音 坪単価（105・20位・0） | money/custom-home-soundproof-price-guide | 検索者は防音工事の坪単価を知りたい可能性が高いのに、記事は注文住宅の話。タイトルもスペース区切りのキーワード並べ |
| 3 | シェアハウス×地名×音大生（計約300・0） | soundproof-rental/music-student-property-search-guide | 探索型クエリに対し、記事は「ふつうのシェアハウスに防音室を置けるか」という別の問いに答えていた。タイトルは「物件探し」でクエリ語なし |
| 4 | 日本の防音市場（92・20位・0） | business/japan-soundproof-market-size | 数字が欲しいクエリなのに、タイトルに数字がない |
| 5 | マンション 楽器 何時まで（7〜9位・CTR約2%） | knowledge/mansion-instrument-practice-time-rules | タイトルで「9〜21時」と答えが完結しているうえ、導入は「平日9時〜20時ごろ」で数字が食い違っていた |
