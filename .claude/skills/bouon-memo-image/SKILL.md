# BouonLab メモ画像（ポケットに入れておく1枚）

## 目的

記事の中の**複数の説明を、1枚の画像で見渡せるようにする**。読者がスクリーンショットで保存し、打ち合わせ・内見・買い物の場面でポケット（スマホ）から取り出して使える**メモのような存在**にする。

- 装飾ではなく「理解を短縮する図」（`bouon-growth-ops`のビジュアル設計方針と同じ考え方）
- 記事を読み切れない人にも、比較・選択・確認の要点だけは持ち帰ってもらう
- 本文の代わりではない。**本文の確認済みの事実を要約したもの**

## いつ作るか

| 状況 | 作る型 |
|---|---|
| 選択肢2〜4つを見比べて選ぶ記事（解決策・依頼先・製品など） | `compare`（比較メモ） |
| 条件を順に確認して絞り込む記事（「予定があるか」「費用優先か」など） | `flow`（判断フロー） |
| 契約前・購入前・打ち合わせ前に確認する項目が5項目前後ある記事 | `checklist`（チェックリスト） |
| 相談・申込の前に自分の条件を整理させたい記事 | `fill-in`（書き込み式。記入線と例つき） |
| 考える観点が8項目前後あり、一覧で見たい記事 | `lookup`（8項目早見） |

作らない場合: 本文が短い（約3,000字未満）、表1つで足りる、1枚に載せると文字が小さくなる、根拠のない数値を載せたくなる。

**1記事につき1〜2枚まで**。増やしすぎると本文より画像が主役になり、スマホで読みにくくなる。

## デザイン仕様

- **サイズ**: 幅1080px固定、高さは内容に合わせて自動（約1,000〜2,000px）。1枚で縦にスクロールせずスクショできる長さに収める
- **配色**: サイトのダーク配色に合わせる（`templates/memo-common.css`の`:root`）。背景`#17120e`、カード`#241c15`、アクセントはゴールド`#d4af37`、注意は`#e6a56a`、OKは`#8fc9a0`
- **フォント**: BIZ UDPゴシック → Noto Sans JP → 游ゴシック → メイリオ（Windows標準で描画できる順）
- **文字サイズ**: 本文27〜29px、補足24px以上（スマホで潰れない下限は24px）。見出し（h1）は54px・2行まで
- **量の上限**: カード3〜4枚、1カード5行以内、1行60字以内。文末を「。」で終わらせる文は1行1文
- **構成**: ①ラベル「保存版メモ」（書き込み式は「書き込み式メモ」）→②見出し（強調語は`<em>`でゴールド）→③リード1〜2行→④カード→⑤（必要なら）`.bar`で一番伝えたい1行→⑥フッター（注記＋「防音Lab」）
- **型ごとの部品**: `compare`は`.card`＋`.num`＋`.row`（`.tag`＋`.val`）。`flow`は`.card`＋`.arrow`（▼）＋`.two`（2分岐）。`checklist`・`fill-in`は`.check`（`.cb`の□、`.fill`の記入線、`<small>`で補足・例）。`lookup`はカード1枚に`.row`を8本

## 文言ルール（必ず守る）

1. **本文で確認済みの事実だけを載せる。画像だけに新しい事実を足さない**
2. 数値は出典のあるものだけ。期間・価格の「目安」は、フッターに出典と目安である旨を書く
3. 費用の具体額は、本文で出典つきで確認済みの場合のみ。迷ったら「記事内のリンク先で確認」とする
4. 「完全」「必ず」「最安」などの断定を使わない。判断を他人に委ねすぎない言い方（「〜を確認」「〜を検討」）にする
5. 医療・健康・税務・金融の断定を載せない。必要なら「専門家に確認」を入れる
6. 賃貸の注意（原状回復・許可）、換気・結露などの二次的リスクを省かない（`00_Persona-Omega.md`のルール）
7. 特定サービス名・広告・アフィリエイトの文言を入れない（広告は別管理）
8. 人物の顔・実在の他社ロゴ・他サイトの画像を使わない

## 作り方（手順）

1. **本文から要点を抜く**: 記事の表・箇条書きから、確認済みの事実だけを選ぶ。型を決める（上の表）
2. **テンプレートをコピー**: `templates/{compare,flow,checklist}.html`と`memo-common.css`を、作業フォルダ（例: `.workspace/.task/{案件}/images-src/`）にコピーする。HTMLの`［　］`を実際の文言に置き換える
3. **描画する**（高さは自動）:
   ```bash
   node .claude/skills/bouon-memo-image/scripts/render-memo.mjs <入力.html> src/content/ja/{category}/{slug}/memo-{名前}.png
   ```
   Chrome / Edgeを使う（`CHROME_PATH`で上書き可）。追加パッケージは不要
4. **目視確認**（画像を開いて見る）: フッターが切れていないか／1文字だけ孤立した折り返し（例:「結／露」）がないか／本文より文字が小さくなっていないか／文言ルールに違反していないか
5. **記事に配置**:
   - 置く場所は、該当の説明が終わった直後（比較表の直後、チェック項目リストの直後など）
   - 直前に**独立した1文の導入**を入れる（例:「保存して見返せる1枚にまとめました。」「打ち合わせに持っていける1枚にまとめました。」）
   - 書式は`![alt](./memo-xxx.png)`（既存記事と同じ。ファイルは記事フォルダ直下）
   - altは「何についての、どんなメモか」を1文で（例:`…の向く人・注意点・期間目安の比較メモ`）
6. **ソースを残す**: HTMLは作業フォルダに保管する。本文の事実を変えたらPNGを再生成する（画像だけ古くならないようにする）

## Claudeへの指示テンプレート（コピーして使う）

```
記事「{タイトル}」（{パス}）に、ポケットに入れておくメモ画像を1枚作って。

目的: 記事内の複数の説明（{比較する選択肢／判断の手順／確認項目}）を1枚で見渡せるようにし、
スクショして{打ち合わせ／内見／購入前}に持っていけるメモにする。
型: {compare | flow | checklist | fill-in | lookup}
載せる内容: 本文で確認済みの事実だけ。画像だけに新しい事実を足さない。
制約: bouon-memo-image skillのデザイン仕様（幅1080・ダーク配色＋ゴールド・本文27px以上・
カード3〜4枚・1行60字以内）と文言ルールに従う。広告・サービス名・断定表現は入れない。
手順: テンプレートをコピー → 文言を置換 → render-memo.mjsで描画 → 画像を開いて目視確認 →
記事に導入1文とaltつきで配置。
```

## AI画像生成を使わない理由

日本語の文字が崩れやすく、比較表や数字の誤りが目立つため。メモ画像は**HTMLを描画**して作る（`generate-image.js`はカバー画像・雰囲気画像のみ。`bouon-writing`の`references/cover-image-fallback.md`を参照）。
