# /draft-plan — ドラフト記事ブレストコマンド

**引数**: ファイル名（省略時は \_draft/ 内の記事ドラフトを一覧して選択を促す）  
例: `/draft-plan 防音賃貸の入居待ち期間にやるべき代替策.md`  
例: `/draft-plan` （一覧から対話で選択）

---

## このコマンドの役割

ファイルを書き出す前に「どんな記事にするか」を対話で固める。  
**ファイルの書き込みは行わない**。提案 → フィードバック → 修正のループを繰り返し、  
方向性が固まったら `/publish-draft {ファイル名}` への引き渡しを提案する。

---

## Step 0. 事前ロード（毎回必ず実行）

以下を読み込んで分析の土台にする。

1. `CLAUDE.md` — ライティング基本ルール・カテゴリ定義
2. `.agents/bouon-writer.md` — 本音と建前シンキングルール（表面の検索意図の裏にある読者心理を掘り下げる）
3. `.agents/persona/01_Consumer-Personas.md` — ペルソナA〜G（読者プロファイル）
4. `.agents/persona/00_Persona-Omega.md` — 編集長フィルター（誇大広告・物理的根拠・二次リスク）

---

## Step 1. ドラフト一覧と選択

`$ARGUMENTS` が空の場合:

1. `_draft/` 内の `.md` ファイルをスキャンする
2. 以下を**スキップ**してリストから除外する:
   - `strategy-` / `cluster-ideas` / `owner-renovation-cluster` で始まるもの（企画ドキュメント）
   - 本文が構想メモのみのもの
3. 対象ファイルを番号付きで表示し、どれをブレストするか聞く

```
_draft/ に以下の記事ドラフトがあります:

1. 在宅ワーク騒音を住環境別に解決する実践ガイド.md
2. 防音賃貸の入居待ち期間にやるべき代替策.md
3. 「旅する防音」ヤマハの防音室体験.md
...

番号または「全部」で対象を選んでください。
```

`$ARGUMENTS` がある場合: 指定ファイルのみ処理。

---

## Step 2. ドラフト分析と提案カード生成

選択されたファイルを読み込み、以下の「提案カード」を1記事ずつ出力する。

ドラフト内に **`> [!forAI]`** ブロックがある場合は、**方向性・カテゴリ・読者・主張の前提をそこから最優先で取り込み**、提案カードの「方向性」「ペルソナ」「見出し案」と矛盾させない（ブロックは企画・清書用であり、本番記事本文には載せない）。

---

### 提案カードのフォーマット

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📄 {ファイル名}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 現状分析
ドラフトの現在の状態（骨格のみ / 一部本文あり / ほぼ完成）と
欠けている要素を1〜3行で説明する。

## 🎯 方向性の提案

**メインアングル（切り口）**:
  この記事が「なぜ今これを読むべきか」の核心を1文で。
  例: "防音賃貸の入居待ちを「準備期間」として逆手に取るサバイバルガイド"

**差別化ポイント**:
  既存記事との違い。何が新しいか、何をカバーしていないかを明示。
  src/content/ の既存記事と被らないことをGlobで確認してから記述する。

**記事の結論（リード文の核）**:
  読者が持ち帰る「1つの答え」を先出しする。

## 👤 ターゲットペルソナ

**主ペルソナ**: A〜Gの中から最適なものを選び、その理由を1行で。
**検索意図**: この読者が打ち込んでいるであろうキーワード3〜5個。
**読者の状態**: 記事を読む前の心理状態・悩みを具体的に描写。

## 📏 推奨ボリューム

**推奨**: Small / Medium / Large
**目標文字数**: {数値}〜{数値}字

**理由**:
  - テーマの深さ（浅い解説 vs 意思決定サポート）
  - 内部リンク先が充実しているか（委譲できるならSmallでよい）
  - アフィリエイト訴求の有無（高単価ほどLargeが有効）

## 🎭 トーン & マナー

**ペルソナボイス**: 本コマンド末尾「トーン選択の早見表」のどのセグメントか
**文体スタイル**:
  - PREP（結論→理由→例→結論）/ QUEST（冒険型）/ PASONA（課題解決型）
  - 敬体（です・ます）、専門度（初心者寄り / 中級者 / プロ向け）

**避けるべき表現**:
  Persona Ω チェックで引っかかりそうな誇大表現・リスク忘れ

## 🗂️ 提案見出し構成

ドラフトの骨格を活かしながら、不足・過剰を修正した H2/H3 構成案。

```

[リード文]（結論先出し・100〜200字）

## {H2-1}

### {H3}（必要な場合）

## {H2-2}

...

## まとめ

## 次のステップ（内部リンク）

```

想定文字数を各H2単位で括弧内に示す。例: `## 対策の選び方（300字）`

## 💰 マネタイズ提案（任意）

アフィリエイトや内部導線の提案。高単価記事（防音室・防音賃貸）ではPASONA/QUESTを起動する。

---
フィードバックをどうぞ！変更したい点・追加したいアングル・削除したい見出しがあれば教えてください。
「OK」で次の記事へ進みます。「確定」でブレスト完了→ /publish-draft への引き渡し案内をします。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## Step 3. 対話ループ（フィードバック処理）

ユーザーの発言を以下のパターンで解釈して応答する。

| ユーザー発言                 | 対応                                                 |
| ---------------------------- | ---------------------------------------------------- |
| `OK` / `次` / `次の記事へ`   | 次のドラフトの提案カードを出力                       |
| `確定` / `これでいく`        | Step 4へ進む                                         |
| `もっと短く` / `Smallにして` | ボリュームを下げた新しい見出し構成案を提示           |
| `もっと詳しく` / `Largeで`   | ボリュームを上げた構成案を提示（H2追加・FAQ提案）    |
| `アングルを変えて`           | 別の切り口（2〜3案）を提示して選んでもらう           |
| `ペルソナを変えて`           | 別ペルソナ向けに読者像・KW・見出しを調整して再提示   |
| `{具体的な指示}`             | 指示の内容に応じて提案カードの該当箇所を更新・再出力 |
| `全部見直して`               | 提案カードを丸ごと再生成                             |

**対話の原則**:

- 変更点のみを差分で示す（提案カード全体の再出力は「全部見直して」のときだけ）
- 変更の理由を1行で添える
- 「なぜそのアングルを選んだか」を聞かれたら根拠（ペルソナの検索意図・既存記事との差別化）を説明する

「確定」が出たら以下を出力する。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ ブレスト完了: {ファイル名}

【確定した方向性サマリー】
- アングル: {1行}
- ペルソナ: {1行}
- ボリューム: {Small/Medium/Large} / {目標文字数}字
- トーン: {1行}
- 見出し: {H2の数}本構成

【次のアクション】
以下のコマンドで本番記事を生成できます:

  /publish-draft {ファイル名}

確定した見出し構成はそのまま引き継がれます。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

複数ファイルを処理した場合は、まとめて出力する。

## 分析の観点（提案カード生成時に内部参照）

### ボリューム判断の基準

| 判定       | 条件                                                         |
| ---------- | ------------------------------------------------------------ |
| **Small**  | チェックリスト型・FAQ型・ハブ補助線・内部リンク先が充実      |
| **Medium** | 一般解説・比較記事・シナリオガイド                           |
| **Large**  | ピラー記事・高単価商材・意思決定サポート・QUEST/PASONAが有効 |

### アングル発見の手順

1. ドラフトの「タイトル案」と「本文の主張」を読む
2. `src/content/` 内の近接記事をGlobで確認し、**被りを避けた切り口**を探す
3. ペルソナの「検索意図」に最も刺さる「Before/After」を設定する
4. Persona Ω フィルター: 誇大広告・物理的根拠なし・二次リスク忘れがないか確認
