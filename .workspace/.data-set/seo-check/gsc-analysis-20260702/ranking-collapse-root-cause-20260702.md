# ランキング崩壊の根本原因調査レポート（2026-07-02）

## 結論（先出し）

**【2026-07-02追記・位置づけ更新】** 本レポート作成後、ユーザーから「URL構造の切り替え＋記事整理による404化が主因ではないか」との指摘を受け、zenki全データ（クエリ920件・ページ521件）を対象に再監査した（`redirect-gap-full-audit-20260702.md`）。その結果、**旧Hugo `/posts/`形式のURLが207件zenki期間にアクセスを持ち、うち138件（67%）がリダイレクト未登録のまま404化していたことが判明**。これは前回把握していた32件の4倍以上の規模で、失われた表示回数は合計約13,345件（zenki全ページ表示回数の約26%）に達する。

**したがって現時点での結論は以下の通り更新する**: サイト全体の崩壊の**主因はURL構造変更＋記事整理に伴うリダイレクト未整備（138件超）**であり、以下に記す`site`ドメイン誤記は**主因に追い打ちをかけた副次的要因**という位置づけが妥当。両者とも技術的には修正済み。詳細な内訳は`redirect-gap-full-audit-20260702.md`を参照。

---

*以下は当初（副次要因として位置づけ更新前）に作成した`site`ドメイン誤記に関する調査内容。*

`astro.config.mjs`の`site`設定に本番ドメインの誤記（`bouon-lab.online`）があり、これが少なくとも2026-04-13〜04-25の期間、サイト全体の`canonical`タグ・サイトマップURL・OGP絶対URLに反映されていた。`bouon-lab.online`はDNS解決不可（実在しない）ドメインであることを確認済み。

この誤記は本セッションでの`git`履歴調査と実際のDNS確認により**確定した事実**。ただし「Googleが具体的にどのエラー（インデックス登録レポートのどの項目）としてこれを検知していたか」「手動対策の有無」は、このツールからは確認できずユーザーのGSC UI確認が必要（後述）。

---

## 確定した事実（git履歴 + DNS確認）

### 1. `astro.config.mjs`の`site`フィールド誤記タイムライン

| 日付 | コミット | `site`の値 | 状態 |
|---|---|---|---|
| 2026-04-02 | `cdcdd8a`（Initial commit） | 未設定 | `astro.config.mjs`に`site`フィールドそのものが存在しない |
| 2026-04-13 | `83e325c`（"rebuild"） | `https://bouon-lab.online` | **誤ったドメインで初めて設定される** |
| 2026-04-25 | `858d2bb`（"renew"） | `https://bouon-lab.com` | 修正（[[project_domain]]memoryと一致） |
| 2026-05-02以降 | `96e6446`ほか | `https://bouon-lab.com` | 正しい状態が継続 |

`public/robots.txt`の`Sitemap:`行も同じタイムラインで誤記→修正されていたことを確認済み（`83e325c`時点で`https://bouon-lab.online/sitemap-index.xml`）。

### 2. `bouon-lab.online`はDNS解決不可（実在しないドメイン）

```
WebFetch https://bouon-lab.online/ → getaddrinfo ENOTFOUND bouon-lab.online
```

つまり期間中、以下が同時に発生していた可能性が高い。

- **全ページの`canonical`タグ**（Astro/Starlightは`site`設定を基に絶対URLを生成）が、存在しないドメインを指していた
- **`sitemap-index.xml`に列挙されるURL**も同様に存在しないドメインを指していた
- GSC上の検証済みプロパティは`bouon-lab.com`のはずなので、サイトマップ経由で送信されるURLがプロパティと不一致となり、GSCがサイトマップを正しく処理できなかった可能性がある
- Googlebotが`bouon-lab.com`の各ページをクロールした際、`canonical`が別ドメイン（しかも存在しない）を指しているのを見て、正規URLの判定に迷い、インデックスを見送る・評価を分散させるという典型的な技術的失敗パターンに合致する

### 3. `robots.txt`自体が2026-04-02〜04-13の間、リポジトリに存在しなかった

`git log --follow public/robots.txt`で確認したところ、最初のコミットは`83e325c`（2026-04-13）。Initial commit（2026-04-02）時点では`public/robots.txt`がgit管理下になかった。デプロイ環境側で別途配置されていた可能性はあるが、**すくなくとも2026-04-02〜04-13の期間、`robots.txt`の状態はこのリポジトリからは検証不能**。

### 4. カテゴリフラット化（2026-06-01）のリダイレクトは網羅的で問題なし

`astro.config.mjs`の"Phase 1〜3"リダイレクトブロックを確認したところ、旧サブカテゴリ構造（`soundproof-room/others/`・`soundproof-room/solution/`等）から現行フラット構造への転送は**全件対応済みで抜け漏れが見当たらない**。このタイミング（kouki期間の後半）での追加的な技術的損傷の可能性は低いと判断。

## タイムラインとGSC期間の重なりに関する留保

**この調査で確認できた誤記期間（少なくとも2026-04-13〜04-25）は、GSCの`kouki`期間（2026-03-06〜06-30）の内側に収まる**が、以下の理由で「これだけで崩壊の全期間・全量を説明できる」と断定はできない。

- `kouki`の崩壊開始日（2026-03-06）は、このリポジトリのgit履歴（開始2026-04-02）より**約1か月前**。つまり2026-03-06時点で何が起きていたか（Hugo→Astro移行がいつ本番反映されたか等）は、このツールから直接確認できない
- `site`未設定期間（2026-04-02〜04-13）と誤ドメイン期間（04-13〜04-25）を合算すると**少なくとも約3週間**は技術的に不健全な状態だったことは確実だが、それ以前（2026-03-06〜04-02）の状態は不明
- 本番デプロイのタイミングとgitコミットのタイミングが一致しているとは限らない（デプロイが遅れていた/先行していた可能性もゼロではない）

→ **推定として最も筋が通るシナリオ**: Hugo→Astro移行のタイミングが2026-03-06前後で、その移行作業の初期段階で`site`ドメインが未設定または誤記のまま本番公開され、少なくとも2026-04-25まで（一部期間は`robots.txt`もgit管理外）その状態が続いた。この間、Googleは新URL構造への評価を正しく引き継げず、サイト全体の信頼スコアが希薄化した。

## ユーザーに確認をお願いしたい情報（GSC UI）

このツールからは取得できないため、以下をGSC UIで確認いただけると、上記の仮説を裏付け・確定できる。

1. **「ページのインデックス登録」レポート**（設定 → インデックス作成 → ページ）
   - 2026年3月〜5月頃に「代替ページ（適切な canonical タグあり）」「送信された URL がクロールされましたが、インデックスに登録されていません」等のエラーが急増していないか
   - 特に`canonical`関連のエラー（Google が別の URL を正規と選択、など）の件数推移
2. **「サイトマップ」レポート**（設定 → インデックス作成 → サイトマップ）
   - 2026年3〜4月頃に「取得できませんでした」エラーや、送信URL数と検出URL数の急な乖離がないか
   - 過去のサイトマップ送信履歴に`bouon-lab.online`関連のエラーメッセージが残っていないか
3. **「手動対策」レポート**（設定 → セキュリティと手動対策 → 手動対策）
   - 「問題は検出されませんでした」であることの確認（通常はこれで一括終了）
4. （可能であれば）**URL検査ツール**で、崩壊前後の任意の記事URL（例：`/ja/soundproof-room/bouon-osusume-hikaku/`）を検査し、「ユーザーが指定した正規URL」と「Google が選択した正規URL」が一致しているか、過去のクロール日時の推移を確認

この4点、特に1・2が確認できれば、今回の仮説（`site`ドメイン誤記が主因）が裏付けられるか、あるいは別の要因（インデックス未登録の理由がcanonical以外）かを切り分けられる。
