## 現在の状況（2026-10-06更新）

### 結論

1. **主因の見立ては7月から変わらない。** 旧URL構造（Hugo `/posts/`・旧カテゴリ階層）から現行構造への切替と記事整理で、旧URLが404・未転送のまま残ったこと。`site`ドメイン誤記は副次要因
2. **技術的に対応が完了したのは2026-09-25〜10-06で、7月ではない。** 7月に`astro.config.mjs`へ追記した138件の転送は、静的ビルドでは301でなく**meta refresh（200＋noindex＋canonical）**として出力されており、Googleに恒久移転として伝わっていなかった（9/25に発覚し、`public/.htaccess`で本物の301に切替）
3. **Googleでの回復は、まだデータで確認できない。** 直近の7日（W41）のGSCは、6月以降の週と同水準。GA4の増加（W40比+37%）はBing・direct・AI系が中心で、Googleの順位回復ではない
4. **手動対策はなし**（2026-10-07確認）。ペナルティが原因ではなく、残るのは「Googleの再クロール・再評価待ち」と「サイトの評価の低さ」

## タイムラインとGSC期間の重なりに関する留保

**この調査で確認できた誤記期間（少なくとも2026-04-13〜04-25）は、GSCの`kouki`期間（2026-03-06〜06-30）の内側に収まる**が、以下の理由で「これだけで崩壊の全期間・全量を説明できる」と断定はできない。

- `kouki`の崩壊開始日（2026-03-06）は、このリポジトリのgit履歴（開始2026-04-02）より**約1か月前**。つまり2026-03-06時点で何が起きていたか（Hugo→Astro移行がいつ本番反映されたか等）は、このツールから直接確認できない
- `site`未設定期間（2026-04-02〜04-13）と誤ドメイン期間（04-13〜04-25）を合算すると**少なくとも約3週間**は技術的に不健全な状態だったことは確実だが、それ以前（2026-03-06〜04-02）の状態は不明
- 本番デプロイのタイミングとgitコミットのタイミングが一致しているとは限らない（デプロイが遅れていた/先行していた可能性もゼロではない）

→ **推定として最も筋が通るシナリオ**: Hugo→Astro移行のタイミングが2026-03-06前後で、その移行作業の初期段階で`site`ドメインが未設定または誤記のまま本番公開され、少なくとも2026-04-25まで（一部期間は`robots.txt`もgit管理外）その状態が続いた。この間、Googleは新URL構造への評価を正しく引き継げず、サイト全体の信頼スコアが希薄化した。
