# 配信者クラスタ：検索ワード予想の設計（前段階）

作成: 2026-10-11 / 状態: 設計案（予想クエリはすべて**仮説**。実データで検証する前提）
上位文書: [cluster-streamer.md](./cluster-streamer.md)（段階S1/S2/S3の定義と記事の仮割り当て）

## 1. 目的と位置づけ

実データ（Bing Webmaster Tools、GSC）は量が少なく、段階の判断に足りない。そこで次の順に進める。

1. **予想**: 段階ごとに「読者が打ちそうな検索ワード」を、決めた型で系統的に作る（このファイル）
2. **検証**: サジェストなどで実在する言い回しを確認し、実データ（Bing・GSC）と突き合わせる
3. **確定**: 的中したクエリで段階を確定し、記事の統合・再構築を決める

予想の目的は、需要を当てることではなく、**検証する候補を漏れなく並べること**にある。予想が外れた部分は、実データとの差として次の予想に戻す（§8）。

## 2. 前提となる仮説（先に潰しておく論点）

| # | 仮説 | 検証方法 | 影響 |
|---|---|---|---|
| H1 | 配信者は「配信」という語を使わずに検索する。「ゲーム 声 近所迷惑」「ワンルーム 夜 大声」「防音ブース おすすめ」のように、**状況や商品で探す** | 実データのクエリに「配信」を含む割合を数える（現状は33件/392件＝約8%） | 「配信」を含むかで記事を分けると、需要を取りこぼす。クラスタの境界が、他のクラスタ（防音室・賃貸・DIY）と重なる |
| H2 | S1は「始める前の不安」を、S2は「具体の症状」を、検索語に出す | 予想クエリを段階別に付与し、実データで当たる割合を段階ごとに見る | 段階分けの妥当性 |
| H3 | S1の需要は「配信」より**「防音」「賃貸」「ワンルーム」「夜中」**側の語に出る | 同上 | S1の入口を配信者向けの記事に置くか、一般の記事に置くか |
| H4 | ゲーム実況・VTuber・歌ってみた・ASMRで、悩みの語が違う（叫び声・台パン・息・環境音） | ジャンル別に予想し、当たり方を比べる | ジャンル別に記事を分ける必要があるか |

H1とH3が外れた場合、配信者クラスタの切り出し方そのものが変わる。**最初に検証する**。

## 3. 読者モデル（段階 × トリガー）

既存資料（ペルソナB、`analysis-streamer-solutions-expert.md` のPhase 1〜3、4大課題）を、検索行動に結びつける。

| 段階 | 読者の状況 | 検索のきっかけ（トリガー） | 知りたいこと | Phase対応 |
|---|---|---|---|---|
| S1 これから始める | 配信前、または開始直後。部屋・予算・近所への影響が不明 | 機材を買う前、引っ越し前、親・同居人に言われた | 「始めて大丈夫か」「いくらかかるか」「どこまで必要か」 | Phase 1 前半 |
| S2 不満を抱えている | 配信中。具体の困りごとがある | 苦情・壁ドン、マイクにノイズが入る、狭い・暑い、台パンが響く | 「どうすれば直るか」「買い替えるべきか」 | Phase 1 後半〜2 |
| S3 すでに安定 | 環境が整っている | 買い替え・節税・引っ越し・スタジオ化 | 「次の選択肢は何か」「損しないか」 | Phase 2〜3 |

S2の代表的なきっかけに「0.8畳で始めて、デスクが入らず暑くて1.5畳に買い換える」がある（4大課題1.3）。「狭い」「暑い」は、S2の検索語の候補になる。

## 4. 予想クエリの生成方法

### 4-1. 生成式

検索ワードは次の5つの部品の組み合わせで作る。1語ずつではなく、**2〜3語をスペースでつなぐ**日本語検索の形に合わせる（実データの上位クエリも「ワンタッチ防音壁 評判」「ベース トラップ 自作」の形）。

| 部品 | 内容 | 例 |
|---|---|---|
| A. 主体 | 誰が | 配信、ゲーム実況、VTuber、歌ってみた、ASMR、ボイスチャット、（主体なし） |
| B. 状況 | どこで・いつ | ワンルーム、賃貸、実家、マンション、アパート、夜中、深夜、同居 |
| C. 音・症状 | 何が起きているか | 声 うるさい、叫び声、台パン、打鍵音、足音、壁ドン、苦情、聞こえる、漏れる、ノイズ、反響、PCファン |
| D. 解決手段 | 何で直すか | 防音、吸音、防音ブース、防音室、防音マット、だんぼっち、OTODASU、ヤマハ、自作、100均 |
| E. 修飾 | 何を求めるか | 安い、1万円、始め方、おすすめ、比較、口コミ、後悔、いくら、費用、賃貸でも、効果 |

### 4-2. 段階別の組み合わせ方

| 段階 | 中心になる部品 | 検索の型 | 例（仮説） |
|---|---|---|---|
| S1 | B（状況）＋D（手段）＋E（予算・始め方） | 「状況＋どうすれば」「始め方」「いくら」 | ワンルーム 配信 防音 / 賃貸 ゲーム実況 近所迷惑 / 配信 始め方 部屋 / 防音 いくらから |
| S2 | C（症状）＋D（手段） | 「症状＋対策」「症状＋原因」 | 台パン 下の階 対策 / マイク ノイズ 部屋 原因 / 防音ブース 狭い 暑い / ゲーム 壁ドン されない |
| S3 | D（手段）＋E（比較・損得） | 「手段＋比較」「経費」「買い替え」 | 防音室 経費 配信者 / 防音ブース 買い替え / 配信スタジオ レンタル 料金 |

### 4-3. 意図タイプ（段階とは別に付ける）

| 意図 | 内容 | 例 |
|---|---|---|
| Know | 仕組みや可否を知りたい | 配信 近所迷惑 どこから |
| Do | 手順・方法を知りたい | ワンルーム 配信 防音 方法 |
| Compare | 比較したい | 防音ブース 比較 / 賃貸 防音 違い |
| Buy | 買う・借りる直前 | 防音ブース 最安 / 防音賃貸 配信 東京 |
| Trouble | 今起きている問題 | 配信 苦情 来た / マイク ノイズ 消えない |

意図で着地記事の型が決まる（Know＝解説、Do＝手順、Compare＝比較表、Buy＝選び方、Trouble＝原因別の対処）。

### 4-4. 生成時のルール

- 部品の全組み合わせは作らない。**各段階の中心部品を固定し、他を1つずつ変える**（1段階あたり50〜80語を上限）
- 「配信」を含む語と含まない語を**ペアで**作る（H1の検証用）。例: 「配信 防音 賃貸」と「ゲーム 防音 賃貸」
- 一般の防音クラスタと重なる語は、段階ではなく「重複」として別に印を付ける（例: 「ワンルーム 防音 安い」）
- 語は予想なので、実在確認の前に記事へ反映しない

## 6. 予想の作成手順

| 手順 | 内容 | 担当 | 出力 |
|---|---|---|---|
| 1 | §4-1の部品表を埋める（A〜E、各10〜20語）。既存の実データ（W40の33件、GA4の流入ページ）と、`.agents/persona/01_Consumer-Personas.md` のペルソナBから語を拾う | Claude | 部品表 |
| 2 | 段階ごとに、中心部品を固定して生成する。「配信あり／なし」のペアで作る | Claude | 予想クエリ一覧（50〜80語×3段階） |
| 3 | サジェストで実在確認する。Googleサジェスト、Bingのサジェストで、予想語の前方一致を取る。候補が出る語を「実在あり」とする | Claude（WebFetch）またはユーザー | 実在確認の列 |
| 4 | 実在確認で出た追加語を、一覧に足す（予想になかった言い回し） | Claude | 追加語 |

手順3は、検索エンジンの自動補完の応答を使う。件数（需要の大きさ）は分からず、**語が実在するかの確認**にとどまる。需要の大きさはキーワードプランナーか実データで見る。

## 8. 評価（予想の当たり方を見る）

実データが入ったあとに、次を集計する。

| 指標 | 見方 |
|---|---|
| 的中率（段階別） | 予想語のうち、サジェストまたは実データで確認できた割合。S1とS2で差があるか |
| 配信語の有無（H1） | 実データのうち「配信」を含まないクエリの割合。多い場合は、クラスタを「配信」で切らず、状況・症状で切る |
| 重複（H3） | 一般クラスタ（防音室・賃貸）と重なるクエリの割合。重なる場合は、一般記事側に入口を置く |
| 取りこぼし | 実データにあって予想になかった語。新しい部品（A〜E）に追加する |
| 空振り | 予想はしたが実在も実データもなかった語。その型を使うのをやめる |

**判断の目安**（案）。S1で的中率が低く、実データにも出ない場合は、配信者の需要自体が小さい可能性がある。その場合、約50本を段階別に整えるより、入口2〜3本に絞って残りを縮小する選択肢を取る。

## 9. 作業の順序と判断点

> 進捗（2026-10-11）: 最初のシード「防音室 配信者」のGoogle・Bing取得とその分析が完了。結果は `../query-check/analysis_防音室-配信者.md`。H1とH4は検証できず、S1が「部屋を整える前」と「防音室を検討中」に分かれる可能性が出た。

1. 部品表（A〜E）を作る（Claude）

3. サジェストで実在確認する（Claude。WebFetchで自動補完の応答を取る方法を試す。取れない場合はユーザーの手作業）

5. 照合して§8を集計する（Claude）
6. 結果を`cluster-streamer.md`に反映し、段階の割り当てを確定する
