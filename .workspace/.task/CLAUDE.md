## 2. 読み方（インデックス優先）

トークンと時間を節約するため、**全文を読まず索引から入る**。

1. `task-list.md` と `schedule-task.md` は、まず冒頭の**索引表だけ**読む
2. 関連IDの本文だけを読む。`task-list.md` は見出し（`### T-NN`）をキーに Grep、`schedule-task.md` は索引の「個別ファイル」を開く。月次解析の個別ファイルは、旧W-NNの見出し（`### W-NN`）をキーに Grep できる。`archive/` は重複確認が必要なときだけキーワードで Grep し、全文は読まない
3. 旧W-NNの経緯・W41/W42の週次生データは、経緯を確かめるときだけ `archive/weekly-task-archive-20261017.md` を Grep する

| やりたいこと | 読むもの |
|---|---|
| 今日何をするか決める | `task-list.md` 索引 → 該当T-NN |
| 月次のGSC/GA4取込後の確認 | `schedule-task.md` 索引で、その月の月次解析のS-NN（例: S-11）→ 個別ファイル |
| 施策の効果判定 | 月次解析のS-NNの該当節と、`access-data/2026/m{MM}/` |
| 新規タスク追加前の重複確認 | 両索引 → `archive/task-list-index.md` → 必要なら archive をキーワード Grep |

## 3. 項目の書き方

- 見出し形式: `### T-NN タイトル`。月次解析の個別ファイルでは、施策ごとに `### 対象（実施日）` の節を作る（旧W-NNはIDを残す）
- 新規IDは**末尾の最大番号+1**。欠番は再利用しない。新しい効果測定にはW-NNを振らない
- 追加・変更・完了のたびに、**同じ編集内で索引表も更新**する（索引と本文の食い違いを作らない）
- 索引の列
  - `task-list.md`: ID／区分／タスク／担当（ユーザー・Claude）／関連（S-NN）
  - `schedule-task.md`: ID／日付／タスク／担当／状態／個別ファイル／関連
- 効果測定の節には、可能な限り**実施日・対象URLまたはクエリ・基準値・見る指標・判定基準**を書く
- 日付は絶対日付（YYYY-MM-DD）で書く。「来週」「次回」だけで済ませない

## 4. 振り分けルール

| 条件 | 置き場所 |
|---|---|
| 今すぐ着手できる（データ不要） | `task-list.md` |
| 次の月次データが揃わないと判断できない | その月の月次解析のS-NNの個別ファイルに節を足す |
| 数か月かけて見る推移・仮説 | 月次解析の「継続観察」節。毎月の解析で次のS-NNへ引き継ぐ |
| 月次の観測数値 | `access-data/2026/m{MM}/README.md`（`/monthly-ppdca`の記録）。タスクファイルには写さない |
| ユーザーの手作業が必要（GSC UI・管理画面等） | `task-list.md`、担当列に「ユーザー」。月次解析の日に行う確認は、そのS-NNの手順に書く |

- **同一テーマは1か所に集約**し、他方は ID で参照するだけにする
- 状態遷移: 月次解析のS-NNで確認 → 着手可能な施策が出たら `task-list.md` へ新規T-NNとして起票（関連列にS-NNを記載）→ 施策を実施したら、効果確認の節を次の月次解析のS-NNに足す
- 「データ待ち」と「今すぐ着手」が混在する項目は分割し、前者を S-NN の節、後者を T にする
- 施策の実施から月末まで日が浅い（月の後半に入った）ものは、その月のデータでは途中経過として扱い、判定は翌月の月次解析で行う

## 5. 更新タイミング

| タイミング | 作業 |
|---|---|
| 月初の月次解析（`/monthly-ppdca`。取得は翌月2〜3日） | その月のS-NNの個別ファイルに沿って確認し、各節の「結果」を書く → 次の月の月次解析のS-NNを起票して、続ける項目を送る → 新規の施策はT-NNに起票 |
| 施策を実施した直後 | 効果確認の節を、次の月次解析のS-NNの個別ファイルに**その場で足す**（実施日・対象・見る指標・判定の月）。後回しにしない |
| タスク完了時 | 下記「アーカイブ」へ |
| 月初 | 両索引を見直し、完了したS-NNとT-NNを`archive/`へ移す |

## 6. アーカイブ

- **T-NN 完了**: `archive/task-list-index.md` で次番号を確認 → `archive/task-list-NN.md` を新規作成 → 索引に1行追記し「次の番号」を更新 → `task-list.md` の本文と索引行を削除。`task-list.md` に「完了タスク」セクションを作らない
- **S-NN 完了**: 個別ファイルの状態を「完了」にして `archive/` へ移し（`git mv`）、`schedule-task.md` の索引行を「完了」節の1行に置き換える。個別ファイルを参照している他のファイルのパスも直す
- 復活が必要な場合は、理由を明記して該当マスターに**新しいID**で戻す

## 7. 禁止事項

- 同一内容を `task-list.md` と `schedule-task.md` の両方に詳細記載すること（片方に集約し、もう片方は ID 参照）
- 索引を更新せずに本文だけ追加・削除すること
- `weekly-task.md`・`effect-monitoring.md` への新規追記
- `archive/` の確認なしに、過去に完了・却下した施策と類似するタスクを起票すること
- 期間の違うデータ同士（週次7日と月次、暦月と30日など）を、日平均にせずに比較すること（取得期間は `access-data/gsc-periods.json` と各月の `README.md` に必ず記録）

## 8. 日付指定タスク（`schedule-task.md`）

「この日に実施・確認する」と日付が決まっているタスク（期限・効果測定・エクスポート予定日など）の置き場。

- **索引**: `schedule-task.md`（日付順。ID `S-NN`、欠番は再利用しない）。**個別ファイル**: `schedule/YYYY-MM-DD-<slug>.md`（1タスク1ファイル。背景・手順・判定基準・完了条件・結果を書く）
- **効果測定は月次解析にまとめる**: 毎月、月初の解析日（翌月2〜3日）を日付にしたS-NN（`schedule/YYYY-MM-02-m{MM}-monthly-analysis.md`）を1本作り、その月に見る施策を節として並べる。個別ファイルに分けた効果測定も、日付は月次解析の日にそろえ、索引の日付欄に「（S-NN内）」と書く
- 起票のタイミング: T-NN で「◯月に確認する」と決めた時点。T-NN の側には詳細を書かず、S-NN を参照する1行だけ残す（同一内容の二重記載は禁止、§7）
- 実施したら個別ファイルの「結果」に追記し、索引の状態を更新する
- 日付が過ぎても未実施のものは、削除せず状態を「期限超過」にして理由を書く
