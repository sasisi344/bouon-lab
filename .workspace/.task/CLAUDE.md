# .workspace/.task/ 運用ルール

タスク管理フォルダの**索引と更新ルール**。作業の起点は常にここ。詳細手順（アーカイブ番号・テンプレート）は `bouon-task-ops` skill を参照。

## 1. 2本柱

日常運用は次の2ファイルだけで回す。どちらも**ファイル削除は厳禁**（中身の更新と、完了項目のアーカイブ移動は可）。

| ファイル | 役割 | 項目ID | 時間軸 |
|---|---|---|---|
| `task-list.md` | **今すぐ着手できる**タスクのみ | `T-NN` | 直近 |
| `weekly-task.md` | **データ待ちで確認する項目**（期限・短期・継続観察）と**週次の生データ** | `W-NN` | 短期〜長期 |

- 上記2本とは別に、**日付が決まっているタスク**は `schedule-task.md`（日付順の索引、ID `S-NN`）と `schedule/` 配下の個別ファイルで管理する（§8）
- `effect-monitoring.md` は2026-10-04に `weekly-task.md` へ統合済みの**移行先ポインタ**。新規追記しない。ファイルは削除しない
- 派生ファイル（`qfo-recheck-task-*.md`・`consolidation-candidates-*.md`・`honne-tatemae-rewrite-survey.md` 等。後ろ2つは2026-10-06に`archive/`へ移動済み）は参照・調査用。マスターではない。削除前に両マスターからの参照有無を確認する
- 完了済みは `archive/`（綴りは archive）。索引は `archive/task-list-index.md`

## 2. 読み方（インデックス優先）

トークンと時間を節約するため、**全文を読まず索引から入る**。

1. `task-list.md` と `weekly-task.md` は、まず冒頭の**索引表だけ**読む（各ファイルの先頭約30行）
2. 関連IDの本文だけを、見出し（`### T-NN` / `### W-NN`）をキーに Grep して読む。`archive/` は重複確認が必要なときだけキーワードで Grep し、全文は読まない
3. `weekly-task.md` の「週次生データ」は、解析・比較をするときだけ読む（直近3週分のみ保持）

| やりたいこと | 読むもの |
|---|---|
| 今日何をするか決める | `task-list.md` 索引 → 該当T-NN |
| 次回GSC/GA4データ取込後の確認 | `weekly-task.md` 索引で「確認時期」が合うW-NNを抽出 → 本文 |
| 施策の効果判定 | 該当W-NN本文と週次生データ |
| 新規タスク追加前の重複確認 | 両索引 → `archive/task-list-index.md` → 必要なら archive をキーワード Grep |

## 3. 項目の書き方

- 見出し形式: `### T-NN タイトル` / `### W-NN 対象（実施日）`
- 新規IDは**末尾の最大番号+1**。欠番は再利用しない
- 追加・変更・完了のたびに、**同じ編集内で索引表も更新**する（索引と本文の食い違いを作らない）
- 索引の列
  - `task-list.md`: ID／区分／タスク／担当（ユーザー・Claude）／関連（W-NN）
  - `weekly-task.md`: ID／区分（期限・短期・継続）／対象／確認に使うデータ／確認時期
- `weekly-task.md` の項目には、可能な限り**実施日・対象URLまたはクエリ・見る指標**を書く。判定基準が決まっているものは本文に1行で添える
- 日付は絶対日付（YYYY-MM-DD）で書く。「来週」「次回」だけで済ませず、次回エクスポート予定日を `weekly-task.md` 冒頭に明記する

## 4. 振り分けルール

| 条件 | 置き場所 |
|---|---|
| 今すぐ着手できる（データ不要） | `task-list.md` |
| 次回GSC/GA4データが揃わないと判断できない | `weekly-task.md`（期限指定／短期） |
| 数週〜数か月かけて見る推移・仮説 | `weekly-task.md`（継続観察） |
| 週次の観測数値・SERP所見 | `weekly-task.md`「週次生データ」 |
| ユーザーの手作業が必要（GSC UI・管理画面等） | `task-list.md`、担当列に「ユーザー」 |

- **同一テーマは1か所に集約**し、他方は ID で参照するだけにする（例: GSC1週間固定は T-06 に集約し、W-02 は参照のみ）
- 状態遷移: `weekly-task.md` で確認 → 着手可能な施策が出たら `task-list.md` へ新規T-NNとして起票（関連列にW-NNを記載）→ 完了したら T-NN を archive へ、結果を W-NN へ追記
- 「データ待ち」と「今すぐ着手」が混在する項目は分割し、前者を W、後者を T にする

## 5. 更新タイミング

| タイミング | 作業 |
|---|---|
| 週次のGSC/GA4取込後（`/weekly-ppdca`） | `weekly-task.md` の週次生データに追記 → 該当W-NNの結果を追記 → 新規フォローアップを T-NN / W-NN に起票 |
| 施策を実施した直後 | 効果確認用のW-NNを**その場で起票**（実施日・対象・見る指標・確認時期）。起票を後回しにしない |
| タスク完了時 | 下記「アーカイブ」へ |
| 月初 | 両索引を見直し、確認時期を過ぎたW-NNの結論化（継続／終了／T-NN化）を判断 |

## 6. アーカイブ

- **T-NN 完了**: `archive/task-list-index.md` で次番号を確認 → `archive/task-list-NN.md` を新規作成 → 索引に1行追記し「次の番号」を更新 → `task-list.md` の本文と索引行を削除。`task-list.md` に「完了タスク」セクションを作らない
- **W-NN 終了**（結論が出た・施策を打ち切った）: 本文を `archive/weekly-task-archive-YYYYMMDD.md` に結論つきで移し、`weekly-task.md` の本文と索引行を削除
- **週次生データ**: 直近3週分を超えたら `archive/weekly-task-archive-YYYYMMDD.md` へ移す
- 復活が必要な場合は、理由を明記して該当マスターに**新しいID**で戻す

## 7. 禁止事項

- 同一内容を `task-list.md` と `weekly-task.md` の両方に詳細記載すること（片方に集約し、もう片方は ID 参照）
- 索引を更新せずに本文だけ追加・削除すること
- `effect-monitoring.md` への新規追記
- `archive/` の確認なしに、過去に完了・却下した施策と類似するタスクを起票すること
- GSCの累計値（期間が7日でないエクスポート）を週次比較に使うこと（取得期間は `_inbox/README.md` 等に必ず1行記録）

## 8. 日付指定タスク（`schedule-task.md`）

「この日に実施・確認する」と日付が決まっているタスク（期限・効果測定の確認日・エクスポート予定日など）の置き場。

- **索引**: `schedule-task.md`（日付順。ID `S-NN`、欠番は再利用しない）。**個別ファイル**: `schedule/YYYY-MM-DD-<slug>.md`（1タスク1ファイル。背景・手順・判定基準・完了条件・結果を書く）
- 起票のタイミング: T-NN / W-NN で「◯月◯日に確認する」と決めた時点。T-NN / W-NN の側には詳細を書かず、S-NN を参照する1行だけ残す（同一内容の二重記載は禁止、§7）
- 実施したら個別ファイルの「結果」に追記し、索引の状態を更新する。結果が `weekly-task.md` の項目（W-NN）に関わる場合は W-NN にも追記する
- 月初に、完了した S-NN の個別ファイルを `archive/` へ移し、索引から削除する
- 日付が過ぎても未実施のものは、削除せず状態を「期限超過」にして理由を書く
