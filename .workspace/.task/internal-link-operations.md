# 内部リンク運用ルール（回遊改善 Sprint 3）

最終更新: 2026-04-13

## 目的
- 記事公開時の内部リンク品質を標準化する。
- ハブ導線、次に読む導線、関連記事導線の効果を継続的に測定する。
- 孤立記事を減らし、クラスター単位の回遊率を高める。

## 1. 公開前チェックリスト（必須）
- [ ] 文脈リンクを本文中に最低3本入れる（導入1本、比較1本、行動1本）。
- [ ] `Next Step` が3本表示されることを対象記事で確認する。
- [ ] 重複導線を避ける（`Next Step` と `関連記事` が同一URLにならない）。
- [ ] ハブ経由で2クリック以内に対象記事へ到達できることを確認する。
- [ ] CTA記事（solutions / use-case）への導線を最低1本含める。

## 2. アンカーテキスト規約
- NG: 「こちら」「詳しく」「この記事」など抽象語のみのリンク。
- OK: 検索意図を含む具体語（例: 「防音室 ローン比較の注意点」）。
- 原則: リンク先の主KW + 解決意図（比較/実践/導入）を含める。
- 1記事内の同一アンカー連打を避け、意図別に語彙を分散する。

## 3. リンク先の優先順位
1. 同一クラスター内の記事（同タグ、同ペルソナ）
2. 比較記事（選択肢を横断して判断できる記事）
3. CV導線記事（solutions / use-case）

補足:
- 外部リンクより内部リンクを先に設計する。
- クラスター外リンクを張る場合は、本文に遷移理由を明記する。

## 4. 編集フローへの組み込み
1. 下書き完成後に「公開前チェックリスト」を実施。
2. CMS反映前に、ハブ導線と `Next Step` のリンク先を手動クリック確認。
3. 公開後24時間以内に GA4 で `hub_click` / `next_step_click` / `related_click` の発火を確認。
4. 週次で下記ダッシュボード記録を更新。

- 対象週:

- `search_result_click` CTR:

- 悪化導線（URL/クラスター）:
- AB差し替え候補:

## 6. 悪化判定ルール（暫定）
- `hub_click` CTR が前週比 -15%以上
- 2ページ目到達率が前週比 -10%以上
- 特定クラスターで孤立記事率が 20% 超

上記いずれかを満たした場合は、翌週スプリントでリンク再配置を実施する。
