# .workspace/_sns-post/ 運用ルール（Threads週間ポスト）

防音Lab（Threads `@bouonlab`）の**週間ポストを作成・管理する作業フォルダ**。投稿の中身の作り方（タイプ①小ネタ型／②クエリ疑問オープナー型、検閲フィルター）は `bouon-threads-ops` skill が正本。本ファイルは**週間運用の量・手順・記録・重複防止**を定める。両者が食い違う場合、**週の本数・構成・文量・記録先は本ファイルを優先**する。

## 1. 構成

```
_sns-post/
├── CLAUDE.md                    # 本ファイル（ルール＋調整ログ）
├── w{NN}-threads-post.md        # 作業中の週間ポスト（投稿前のものだけここに置く）
└── archive/
    ├── topic-index.md           # ネタ台帳（過去に何を書いたか・重複防止の正本）
    └── w{NN}-threads-post.md    # 投稿済みの週間ポスト
```

- 作業中のファイルは**常に0〜1本**（その週のもの）。溜めない
- 台帳は `archive/topic-index.md` の1本に集約する。`.agents/threads-ops/postlist.md`・`used-sources.md` は移行済み（新規追記しない）

## 2. 量の決まり

| 項目 | 基準 |
|---|---|
| 週あたり | **2ポスト**（ネタ2本） |
| 1ポストの構成 | **約3スレッド**（1/3・2/3・3/3の連投。自分への返信で連ねる） |
| 1スレッドの文量 | 120〜400字（上限500字）。目安は300字前後で、答えを出す3/3は長くなってよい。1/3は短く切る |
| 1ポスト合計 | ①小ネタ型 350〜600字 ／ ②クエリ疑問オープナー型 700〜1,100字 |
| 標準の組み合わせ | **②クエリ疑問オープナー型×1 ＋ ①小ネタ型×1**。データが足りない週は①×2でもよい |

3スレッドの役割:

| 位置 | ①小ネタ型 | ②クエリ疑問オープナー型 |
|---|---|---|
| 1/3 | 意外な事実・数値のフック（単体で目を引く）＋次への橋渡し | 実検索クエリに近い疑問で書き出す＋数の約束・橋渡し |
| 2/3 | 根拠・比較・身近な例（dB換算、価格差、規約文言など） | 本音の言語化（なぜその疑問を持つか） |
| 3/3 | 使いどころ・一言のまとめ。記事リンクは任意 | 具体的な答え＋リアクションを誘う一文。**記事リンクは3/3に置く** |

- **リンクは1/3に入れない**（リーチ抑制を避けるため、`bouon-threads-ops` の方針を連投に適用）
- **2/3・3/3は単独でも意味が通る**ようにする。**1/3だけは意図的に「未完了」で終える**（§2.1）
- Markdown記法（`**太字**`）は使わない（Threadsでは崩れる）。強調は改行と語順で行う
- ハッシュタグは原則使わない（使うなら1つまで）
- 数値・制度・企業名は元記事の記載を使い、新しい事実主張を足す場合は `bouon-research` skill で裏取りする

## 2.1 続き誘導ルール（1/3でタップさせる）

連投は、1/3だけが単独投稿に見えて「完結している」と読まれると、2/3以降が読まれない。**1/3の末尾で「続きがある」ことを明示し、続きを見る理由を作る。** 次の4つのうち、**#1・#3・#4は全ポスト必須、#2（数の約束）は②クエリ疑問オープナー型で必須、①小ネタ型では任意**とする。

| # | 手法 | やり方 | 根拠となる心理 |
|---|---|---|---|
| 1 | **続きマーカー** | 1/3と2/3の最後の行に `（1/3）👇` `（2/3）👇` を置く。3/3にはマーカーを付けず、締めの問いかけで終わりを示す | 進捗表示は「あと何本か」が分かり読み切りやすくなる。完了を示す終わり方は未完了感を解消する |
| 2 | **数の約束** | 1/3で「3つの物差し」「3ステップ」のように**構造を宣言**する（内容は出さない） | 数を示されると、全部見たくなる（ゴール勾配）。見通しが立つと読む負担が下がる |
| 3 | **情報ギャップ** | 1/3は**問いと「答えがあること」**までで止め、答え本体は2/3以降に置く。答えの一部（条件・数字）を伏せる | 知っていることと知りたいことの差が大きいほど、埋めたくなる（好奇心ギャップ） |
| 4 | **橋渡し1行** | 1/3と2/3の末尾（マーカー直前）に、**次のスレッドで回収する具体的な内容**を1行で予告する | 未完了のものは記憶に残りやすい（ツァイガルニク効果）。何が来るか分かると、タップの心理的コストが下がる |

書き方の例:

```
（1/3末尾）
では何を基準にすればいいのか。答えは3つの物差しにあり、そのうち1つが決まっているかどうかで話が大きく変わります。

（1/3）👇
```

守ること（クリックベイト防止）:

- **予告したものは必ず次のスレッドで回収する。** 回収しない予告、誇大な煽り（「衝撃」「知らないと大損」など）は禁止（ペルソナΩの検閲フィルター準拠）
- 「続きます」「続きはリプ欄で」のような**定型句だけの誘導は使わない**。毎回、予告の中身を変える（テンプレ化防止）
- 絵文字は矢印 `👇` のみ、各マーカーに1つまで
- 予告は事実の範囲で書く。「意外な」「驚きの」のような評価語は、数値や事実で裏づけられるときだけ使う
- 1/3だけ読んで離脱しても、読者に**誤解が残らない**内容にする（1/3の断定は2/3で覆さない）

## 3. 週間ポストの作り方

1. **ファイル名**: `w{NN}-threads-post.md`。`{NN}`は `access-data` と同じ週番号（`weekly-task.md` の週次生データと同じ体系。週は土曜〜土曜の7日）。投稿予定日が属する週で付ける
2. **ネタ選定**（CSV・記事全文を読まない）
   - ②のクエリ: `weekly-task.md` の週次生データ・索引W-NN、`access-data` の `report` 出力にある**実クエリ**から選ぶ。架空のクエリは使わない
   - ①の事実: `.workspace/.data-set/interlink-postlist.md` で記事を選び、**対象記事の該当箇所だけ**読んで1トピックを抜き出す
   - 候補は `archive/topic-index.md` の「ストック」を先に確認する
3. **重複チェック**（必須、§5）→ OKなら作成
4. **ファイル作成**: §4のテンプレートで2ポスト分を書く。文字数をスレッドごとに数えて記入する
5. ユーザーが確認・調整 → ユーザーがThreadsアプリから投稿（投稿の実行は常にユーザー）
6. 投稿したら §6 の手順で記録・アーカイブする

## 5. 重複防止ルール（作成前に必ず実施）

`archive/topic-index.md` を以下のキーワードで検索する（全文を読まない。表の列で絞る）。

| 照合する項目 | 禁止 / 制限 |
|---|---|
| 切り口（同一ネタ） | **再利用しない**（同じ事実・数値を別の言い回しにするのも不可） |
| 検索クエリ（②） | 同一クエリは再利用しない。表記ゆれ（「何時まで」「何時 まで」）も同一とみなす |
| 記事slug | 別の切り口なら再利用可。ただし**同じ記事は連続2週で使わない**。同一記事の2回目は前回から4週以上あける |
| フック型・書き出し | 直近4ポストと同じフック型を連続させない（テンプレ化防止） |
| 同週内 | 2ポストで同じ記事・同じクエリを使わない |

- 迷う場合は「切り口」列を読み比べ、重なっていれば別ネタにする
- 既存の単発下書き `.agents/threads-ops/drafts/query-hook/mansion-instrument-practice-time-rules-query-hook.md` は、最初の週間ポスト作成時に**3スレッド構成へ再編**して取り込む（台帳には登録済み）

## 6. 投稿後の記録とアーカイブ

1. 投稿ごとに、作業ファイルの「投稿」欄に投稿日・URLを記入し、状態を更新する
2. **同時に `archive/topic-index.md` の該当行を更新する**（作成時に行を足し、投稿時に投稿日・URLを埋める）
3. 2ポストとも「投稿済」または「見送り」になったら、ファイルを `archive/` へ移動する（状態=完了）
4. 見送り・持ち越したネタは、台帳の「ストック」へ移し、理由を1行残す。台帳の本表には**投稿したものだけ**を載せる
5. 投稿の1週間後を目安に、台帳の「反応メモ」に表示・いいね・返信の傾向を1行記録する（Threadsのインサイトを見るのはユーザー。数値はユーザーが伝えた範囲で記録する）

## 7. 効果の見方と調整

- 週報（`/weekly-ppdca`）で、GA4の参照元にThreads由来（`threads.net`系）の流入が出ているか、指名検索「防音ラボ」の表示・クリックが動いているかを確認する（`weekly-task.md` W-20）
- **1/3→2/3の到達**を見る: ユーザーがThreadsインサイトで1/3と2/3の閲覧数を伝えたら、比率を台帳の「反応メモ」に残す。2/3が1/3の半分未満なら、続き誘導（§2.1）の予告文を見直す
- 反応の良かった**型・フック・テーマ**を台帳の「反応メモ」から拾い、翌週のネタ選定に反映する。ただし1〜2本の反応で断定せず、同じ型が3本以上たまってから傾向として扱う
- ルールを変えたら、**§8の調整ログに1行追記**する（日付・変更・理由）
