# .workspace/access-data/ 運用ルール

GSC/GA4の月次エクスポートの保管庫（2026-10-16に週次から月次へ移行。W24〜W42は週次の過去データ）。**索引（何がどこにあるか）と作業ログ（何を解析して結論をどこに書いたか）**をここに記録し、次回以降にCSVを読み直すコストを減らす。

## 1. 基本方針（コスト分散）

1. **CSVを先に開かない。** まず本ファイルの索引で「対象週・期間・比較可否」を確認し、結論は各月の `2026/m{MM}/README.md`（月次の記録）で読む。2026-10-17以前の週次の結論は `archive/legacy/weekly-task-archive-20261017.md`
2. **CSVを開くのは新しい解析が必要なときだけ。** その場合も全文 Read はせず、`head` ／ Python集計で必要な列・合計だけ取る（§5のレシピ）
3. **解析した結果は必ず要約して残す。** 数値と結論は各月の `2026/m{MM}/README.md`、解析の履歴は本ファイル§6に1行。CSVの再解析を前提にしない
4. **過去の月・週のCSVは削除しない**（再集計の一次データ）。ただし通常の作業では読まない

## 2. 取得と取り込み（月次）

**何を・どの期間で・どの軸で取るかの正本は `export-spec.md`。** 要点だけ:

- **期間**: 原則は暦月（1日〜末日）。暦月にできない月は「月末日で終わる30日」でもよい
- **取得日**: 月末〜翌月3日（推奨は翌月2〜3日。GSCの直近2〜3日は未確定）。GSCとGA4は同じ日付範囲で取る
- **取るもの**: G1 GSC検索パフォーマンス／G2 ページ×クエリ（Looker Studio）／G3 インデックス登録／A1 GA4 LP／A2 GA4 クリックイベント／A3 GA4 デバイス
- **Googleを優先する。** Bing Webmaster Toolsのデータは取らない（BingはA1の参照元の構成比で参考に見るだけ）

手順:

1. ユーザーがエクスポートを `_inbox/` に置く（ファイル名は問わない）
2. `/monthly-ppdca` が中身（先頭行・列名）で種別を判定し、`export-spec.md` §3のファイル名に直して `2026/m{MM}/` へ仕分ける
3. `templates/monthly-checklist.md` を `2026/m{MM}/README.md` にコピーし、期間・取得日・取得チェック・「この月の出来事」を埋める。**GSCのCSVには期間が書かれない**ので、ここが期間の記録になる
4. `gsc-periods.json` に `"m{MM}": {"span": "month", "start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}` を登録する（30日で取った月は `"span": "30d"`）
5. §3の索引に行を追加する（同じ編集内で）

## 4. データ種別の判定とクセ

| 種別 | 判定方法 | 注意 |
|---|---|---|
| GSC 7日 | 列が `クリック数,表示回数,CTR,掲載順位` の5列のみ | 週次比較に使える唯一の形式。クエリ表は匿名クエリ分が除外され、ページ表の合計と一致しない |
| GSC 3か月＋比較列 | 列名に「過去 3 か月間」が並ぶ（9列前後） | 累計。週次増減には使えない |
| GSC 期間比較 | 列名に `YYYY/MM/DD - YYYY/MM/DD` | 当週と直前期間の比較。直前期間が長い場合は注意（W29） |
| GA4（週次・旧） | 先頭に `# YYYYMMDD-YYYYMMDD` | **行合計は総セッションを超える**（ページタイトル×LP×参照元で分割）。総計は先頭データ行（`,,,207,…,総計`）を使い、参照元は比率で見る |
| GA4（月次 A1〜A3） | 先頭に期間、列は `export-spec.md` §3 | ページタイトル・ページパスを行に入れないので、A1の行合計は総セッションとほぼ一致する。米国などからの`(direct)`はボット疑いとして集計で除外する |

- **GSCはGoogleのみ。** 流入の過半はBing（W41=約51%）だが、**改善の判断はGoogleを優先する**（2026-10-16決定）。サイト全体のアクセスの増減を言うときだけGA4の全体値を添える
- GSCの直近2〜3日は確定前で、GA4で着地があるのにGSCに出ないページがある
- 期間不明のGSCファイルは、まず `wc -l` と上位ページのクリック・表示の桁で規模を推定し、断定せず「期間不明」と記録する

## 5. 集計は `bouon-weekly-report` skill のスクリプトで行う

月次の集計・前月比較・ページ別の月次推移は、CSVを読まずにスクリプトで出す。件数は日平均にそろえて比べる。手順と解釈は `.claude/skills/bouon-weekly-report/SKILL.md`。

```bash
M=.claude/skills/bouon-weekly-report/scripts/monthly_report.py
python $M inventory             # 全月の期間・取得済みファイル
python $M report m11            # 前月比較つき月次サマリー（KPI・順位帯・11〜20位・意図のずれ・affiliate_click）
python $M trend bass-trap       # URL一部一致の月次推移

# 過去の週次データ（w24〜w42）を見るとき
python .claude/skills/bouon-weekly-report/scripts/weekly_report.py report w42
```

**期間は `gsc-periods.json`（本フォルダ直下）に登録する。** スクリプトはこのファイルを正とする。新しい月を取り込んだら、§3の索引と同じ編集で追記する。

### スクリプトを使わず個別に集計する場合のレシピ

```bash
# GSC 7日: 合計とクリックのあった行
python - <<'EOF'
import csv
r=list(csv.DictReader(open('ページ.csv',encoding='utf-8-sig')))
c=sum(int(x['クリック数']) for x in r); i=sum(int(x['表示回数']) for x in r)
print(len(r),c,i,round(c/i*100,2))
for x in r:
    if int(x['クリック数'])>0: print(x)
EOF
```

- GA4: `csv.reader` で `#` 行を除き、先頭データ行の総計と、参照元(3列目)・LP(2列目)の合計を `Counter` で集計。総計行は別扱いにする
- 前週比較: 同じ集計を `w{NN-1}` に当て、**期間種別が両方「7日」のときだけ**差分を出す
- 大きいファイル（W30・W36のページ約700行、M04の217KB）は `head -20` や列指定の集計だけにする

## 7. ルール

- 新しい月を取り込んだら、**§3の索引・`gsc-periods.json`・`m{MM}/README.md`・§6の作業ログを同じ編集で更新**する
- 解析結果の数値を本ファイルに転記しない（二重管理を避ける。数値は各月の `README.md`）
- 取得の仕様（期間・軸・ファイル名）は `export-spec.md` を正とする。軸を変えたら `export-spec.md`・`templates/monthly-checklist.md`・`monthly_report.py` を同じ編集で直す
- GSCは**カスタム期間（GA4と同じ日付）、比較モードなし**で取得する。累計・3か月で取得してしまった場合は再取得する
- 前月と比べるときは、件数は日平均で、比率はそのまま比べる。週次の過去データ（w{NN}）と月次（m{MM}）は比べない
- 別ブログやサイト外の分析データはここに置かない
