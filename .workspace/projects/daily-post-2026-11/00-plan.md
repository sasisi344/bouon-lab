## 4. 品質の条件（毎日でも薄くしない）

- 語り手は「静かな空間で寝たくて防音を調べてきた さしし」。専門家・施工経験者を名乗らない。一人称の体験を作らない（`bouon-writing`「語り手」）

- カバー画像: **生成にはユーザーの指示が要る**。指示がない場合は、画像のプロンプトだけ置いて公開し、まとめて後から作る（hq の画像の流れ）

## 5. 毎日公開の仕組み（段1、CC が実装）

いまは `draft` だけで公開を決めていて、公開日が未来の記事を隠す仕組みがなく、デプロイは月1回の定期実行と push のときだけ。毎日公開を人の手に頼らず回すため、次を入れる（コードの変更なので、ユーザーの承認後に行う）。

1. 記事一覧・記事ページ・検索・サイトマップで、`draft !== true` に加えて「`date` が今日（日本時間）以前」の記事だけを出す（`draft` で絞っている5か所＋サイトマップ）
2. `.github/workflows/deploy-bouon-lab.yml` に毎日の定期実行（日本時間 6:00）を足す。公開日が来た記事が、その朝のビルドで出る
3. デプロイの後、その日に公開された記事の URL を IndexNow に送る手順を足す（キーは公開してよい値、`public/<キー>.txt`）
4. Google には、ユーザーが週1回まとめて URL 検査で登録をリクエストする（1日の上限内で）
